# API-контракты — Профессиональный навигатор

Статус: рабочая документация по фактически реализованным маршрутам. Поле, которого нет в ответе кода, здесь не описано как готовое.

Локальный адрес: `http://localhost:3000`. Формат JSON, UTF-8.

## Общие правила

Идентификатор сессии — заголовок `X-Session-ID` (UUID). Тело `sessionId` у маршрутов, которые читают заголовок, игнорируется.

`X-Session-ID` не является входом в аккаунт. Кто знает UUID, читает и пишет эту сессию. Отдельной авторизации, личного кабинета и синхронизации между устройствами нет. Чтобы вернуться к тем же данным, клиент должен сам сохранить UUID и передать его снова.

Ошибка: `{"error":"описание"}`. У части ответов есть `details`.

| HTTP | Когда это происходит |
|---|---|
| 200 | Трек выбран; чтение вопросов, сессии, рекомендации, рефлексий, каталога, health |
| 201 | Диагностика, уточнения, рекомендация или рефлексия сохранены |
| 400 | Нет валидного UUID в заголовке, тело не JSON, неверный `grade` или `limit` |
| 401 | Заголовка `X-Session-ID` нет |
| 404 | Сессии нет (кроме самого выбора трека); нет диагностики, рекомендации или профессии |
| 409 | Генерация без диагностики или без сохранённого класса; уточнения без диагностики |
| 422 | Тело не прошло схему или вариант уточнения не из каталога |
| 500 | Необработанная ошибка сервера |
| 502 | Пайплайн генерации выбросил исключение. Запись рекомендации при этом не создаётся |
| 503 | База недоступна на health, схема устарела или каталог профессий пуст |

Код генерации не возвращает 504. Нехватка настроек модели не даёт отдельный HTTP-статус: ответ сохраняется как `retrieval_only` и приходит с 201.

## 1. Проверка состояния

**GET** `/api/health`

Сессия не нужна.

`200`:

```json
{
  "status": "ok",
  "database": "connected",
  "service": "professional-navigator-api",
  "aiConfigured": true
}
```

`aiConfigured` равен true, только если заданы `AI_API_BASE_URL`, `AI_API_KEY` и `AI_MODEL`. Это не проверка, что GigaChat ответил. Если база недоступна, статус `503`, `"status": "error"`, `"database": "disconnected"`.

## 2. Выбор трека

**POST** `/api/track/select`

Заголовок: `X-Session-ID: <UUID>`.

Неизвестный UUID создаёт новую сессию. Это не 404. Повторный вызов с тем же UUID обновляет трек.

```json
{
  "trackType": "interests",
  "schoolGrade": 7,
  "confidenceBefore": "medium"
}
```

`trackType` обязателен: `explore`, `interests` или `known_direction`.

`schoolGrade` необязателен: целое число от 1 до 11. Если поле не передано, ранее сохранённый класс не очищается и не заменяется на 9. `0`, `12`, дробь и `null` дают 422, запись не меняется.

`confidenceBefore` необязателен: `low`, `medium` или `high`. Значение дописывается в предпочтения профиля и не затирает остальные ключи. **GET** `/api/session` это поле сейчас не возвращает: в профиле есть только `schoolGrade` и `municipality`.

`200`:

```json
{
  "sessionId": "6f9619ff-8b86-4011-a42d-00cf4fc964ff",
  "trackType": "interests",
  "status": "selected"
}
```

Ошибки: 400, 401, 422, 500. Отдельного 404 на этом маршруте нет.

## 3. Вопросы диагностики

**GET** `/api/diagnostic/questions`  
**GET** `/api/diagnostic/questions?grade=7`

Заголовок сессии не требуется.

Без `grade` — список анкет: `data[]` с `questionnaire_name`, `note`, `questionCount`, и `count`.

С `grade` от 1 до 11 — объект `{ "grade", "questionnaire" }`. В анкете блоки и вопросы с `question_id`, текстом и `options`. Нецелое значение или число вне 1–11 даёт 400: `grade must be an integer between 1 and 11`. Если анкеты для класса нет — 404.

## 4. Отправка диагностики

**POST** `/api/diagnostic/submit`

Сначала нужен трек. Заголовок `X-Session-ID`.

```json
{
  "answers": [
    {
      "questionId": "bilet_q1_subjects",
      "answer": ["Математика", "Информатика"]
    },
    {
      "questionId": "bilet_q6_clubs",
      "answer": ["Основы программирования: меня привлекают алгоритмы и коды"]
    }
  ]
}
```

`answers`: от 1 до 100 элементов, `questionId` уникальны. `answer` — строка до 1000 символов, конечное число, boolean или массив строк (элемент до 500 символов). Варианты нужно брать из полученной анкеты.

В том же теле можно передать необязательный `clarificationAnswers` (1–6). Надёжнее отправить уточнения отдельным маршрутом.

`201`:

```json
{
  "diagnosticId": "ee7eadfb-affa-418b-b0d8-0dd75119c23d",
  "savedAnswers": 2,
  "clarificationId": null,
  "savedClarificationAnswers": 0,
  "status": "submitted"
}
```

Ошибки: 400, 401, 404 `Session not found. Select a track first.`, 422, 503 если нет нужных таблиц, 500.

## 5. Последняя диагностика

**GET** `/api/diagnostic/latest`

Заголовок `X-Session-ID`. `200` содержит ответы и уточнение либо `null`. Если диагностики нет — 404 `Diagnostic not found for this session`.

## 6. Уточняющие вопросы

**GET** `/api/clarification/questions`

Сессия не нужна. Ответ: `{ "data": [...], "count": 6 }`. У вопроса есть `question_id`, `type` (`single_choice` или `multi_choice`), `options[].value`. Свободный текст допустим только у опции с `allow_custom_text`.

**POST** `/api/clarification/submit`

Нужны сессия и уже сохранённая диагностика.

```json
{
  "answers": [
    { "questionId": "agent_q1_likes", "answer": ["tech", "data"] },
    { "questionId": "agent_q2_work_style", "answer": "solo" },
    { "questionId": "agent_q3_tasks", "answer": "analytical" }
  ]
}
```

Для нескольких вариантов — массив значений из каталога. Объект `{ "values": ["other"], "customText": "свой текст" }` только если эта опция разрешает свой текст. От 1 до 6 ответов.

`201`: `{ "clarificationId", "savedAnswers", "status": "submitted" }`.

Если диагностики ещё нет — 409 `Complete the diagnostic before submitting clarification answers`. Неизвестный вопрос или чужое значение — 422. Также возможны 400, 401, 404 и 500.

Уточнения не обязательны для генерации. Обязательны сессия, диагностика и класс.

## 7. Генерация рекомендаций

**POST** `/api/recommendations/generate`

Заголовок `X-Session-ID`. Тело `{}` либо:

```json
{
  "clarificationAnswers": [
    { "questionId": "agent_q5_format", "answer": "offline" }
  ]
}
```

Порядок проверок:

1. Сессия уже создана треком.
2. Есть последняя диагностика этой сессии. Иначе 409 `Complete the diagnostic before generating recommendations`.
3. Если в теле есть уточнения, они проверяются и сохраняются.
4. В профиле есть числовой `schoolGrade`. Иначе 409 `School grade is required before Sofi recommendations`. Класс 9 по умолчанию не подставляется.
5. Результат сохраняется. Успех — HTTP 201 и `"status": "generated"`.

Поля, которые есть и у старых, и у новых ответов: `recommendationId`, `sessionId`, `summary`, `hypotheses`, `trials`, `nextStep`, `nextStepOptions`, `model`, `createdAt`.

Гипотеза:

```json
{
  "professionId": "bf4b0a01-1339-43f2-833d-526faeead862",
  "title": "Разработчик ПО",
  "reason": "Интерес к алгоритмам.",
  "fitScore": 3,
  "scoreKind": "relative_ranking"
}
```

`fitScore` — относительный ранг: сильное совпадение 3, среднее 2, слабое 1. Это не процент и не балл RIASEC ученика. В `hypotheses` попадают только профессии, для которых найден один UUID. Строковые коды вроде `prof_004` в это поле не подставляются.

`nextStepOptions` — всегда три слота в порядке `club`, `college`, `online_course`.

### Возраст

Класс берётся из профиля, сохранённого через track.

**1–4.** `hypotheses` — пустой массив. Профессии и колледжи не показываются. `interestTags` может содержать направления. Все три шага `available: false`, без `title` и `id`. Текст заметки: «Для 1–4 классов показываем направления интересов, без профессий, колледжей и курсов.»

**5–8.** Профессиональные гипотезы остаются. Интересы и предупреждения тоже, если они есть в результате. Колледжи, вузы и образовательные программы в шаги не подставляются: все три слота `available: false`, без названия программы. Заметка: «Для 5–8 классов показываем профессии без колледжей, вузов и образовательных программ.» Если пробное занятие имеет UUID и есть в таблице проб, оно остаётся в `trials`.

**9–11.** Гипотезы и образовательные шаги сохраняются. Слот колледжа может быть `available: true`, если в уже загруженном каталоге есть связанная программа СПО. Кружок или онлайн-курс становится доступным только при реальной записи такого типа. Иначе слот недоступен и ссылка не выдумывается.

Пример недоступного слота для 9–11:

```json
{
  "type": "club",
  "available": false,
  "note": "В проверенном каталоге нет кружка или секции для выбранных профессий. Контакты не выдумываются."
}
```

### Новые поля Софи

Они добавляются и к ответу POST, и к **GET** `/api/recommendations`, когда рекомендация создана модулем Софи.

```json
{
  "interestTags": [
    {
      "industry_id": "ind_003",
      "tag": "Информатика",
      "why": "Нравятся алгоритмы."
    }
  ],
  "warnings": ["llm_fallback_used"],
  "disclaimer": "Это предварительная подсказка, а не диагностика.",
  "generation": {
    "mode": "llm",
    "tier": "5-8",
    "promptVersion": "nav-5-8",
    "catalogVersion": "sha256:0eb9dbee78b76f60f593d82332a3220f99966a0c0b7799348a4454bc8a1287a3",
    "configVersion": "1.0.0+rag-1.2.0+llm-1.1.0+validation-1.1.0",
    "attempts": 1
  }
}
```

`generation.mode` бывает `llm` или `retrieval_only`.

`unmappedHypotheses` есть только если часть гипотез не сопоставилась с одним UUID. У такого элемента `mapping` равен `unmapped` или `ambiguous`, а `professionId` равен `null`. Эти элементы не попадают в основной массив `hypotheses`.

Старая рекомендация с пустым `ai_payload` и пустыми колонками версий не содержит `interestTags`, `warnings`, `disclaimer`, `generation` и `unmappedHypotheses`. Их отсутствие не ошибка. Новые рекомендации эти ключи отдают: списки могут быть пустыми, `disclaimer` может быть `null`, а `unmappedHypotheses` может не быть вовсе.

### retrieval_only

Это успешно сохранённая рекомендация, не HTTP-ошибка. Ответ 201, `"status": "generated"`, `model` равен `retrieval_only`, `generation.mode` равен `retrieval_only`. В `warnings` обычно есть `llm_fallback_used`. Так бывает, если модель не ответила в срок или настройки вызова не позволили получить текст. Повторный **GET** `/api/recommendations` возвращает ту же запись со `"status": "saved"`.

Исключение пайплайна до сохранения — это уже 502 `AI service request failed`, без `recommendationId`.

Другие ошибки генерации: 400, 401, 404 `Session not found`, 409, 422, 503 `Profession catalog is empty` или устаревшая схема, 500.

## 8. Чтение рекомендации

**GET** `/api/recommendations`

Заголовок `X-Session-ID`. `200` повторяет поля generate, но `"status": "saved"`. `trials` загружаются по сохранённым UUID.

Новые поля Софи совпадают с тем, что было в POST для этой записи. Для старой записи их нет.

Если рекомендации нет — 404 `Recommendation not found for this session`. Также 400, 401 и 404, если сессии нет.

## 9. Снимок сессии

**GET** `/api/session`

Заголовок `X-Session-ID`. `200` содержит `sessionId`, `trackType`, `createdAt`, `updatedAt`, `profile`, `diagnostic`, `recommendation`, `reflections`.

`profile` — `{ "schoolGrade", "municipality" }` или `null`. Уверенность до выбора здесь не отдаётся.

`diagnostic` — последняя анкета и вложенное `clarification`, либо `null`.

`recommendation` — последняя рекомендация без полей `status` и `trials`, либо `null`. Возрастные `hypotheses` и `nextStepOptions` те же, что сохранены. Новые поля Софи присутствуют по тем же правилам, что у GET рекомендации.

`reflections` — массив, возможно пустой.

404, если сессии нет. 503, если схема базы устарела.

Восстановление экрана возможно только если браузер снова пришлёт тот же `X-Session-ID`. Другое устройство само сессию не увидит.

## 10. Рефлексия

**POST** `/api/reflection`

```json
{
  "rating": "useful",
  "comment": "Хочу попробовать",
  "recommendationId": "05ad57a0-1863-49b5-a8a4-030d12e35ede"
}
```

`rating`: `useful`, `unsure` или `not_useful`. `comment` и `recommendationId` необязательны. Если UUID рекомендации указан, он должен принадлежать этой сессии, иначе 404.

`201`: `{ "id", "created_at", "status": "saved" }`.

**GET** `/api/reflection` — `{ "data": [...], "count" }` только для текущего заголовка.

## 11. Каталог

**GET** `/api/professions` — активные профессии. Справочный `riasec` относится к профессии, не к ученику. Ошибки чтения дают 500.

**GET** `/api/professions/[id]` — карточка по UUID или старому `external_id`. Нет записи — 404.

**GET** `/api/trials?region=Екатеринбург&limit=20` — активные пробы выбранного региона. `limit` от 1 до 100, иначе 400. Класс ученика этот маршрут не учитывает. Регион по умолчанию — Екатеринбург. Проба без `region_id` в этот список не входит.

## 12. Ограничения текущего MVP

- Организации, образовательные программы и пробы нового каталога Алисы ещё не импортированы полностью. В шагах 9–11 и в `GET /api/trials` видны уже загруженные старые строки.
- Успешный живой ответ GigaChat пока не подтверждён. Контролируемый запуск дошёл до шлюза и сохранился как `retrieval_only` из-за таймаута попытки.
- Нет личного кабинета и автоматической синхронизации между устройствами.
- `GET /api/health` не доказывает, что генерация пройдёт в режиме `llm`.
- Старые рекомендации не переписываются новыми возрастными правилами. Уже сохранённый колледж в старой записи 5–8 класса при чтении останется.
