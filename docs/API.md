
# API-контракты — Профессиональный навигатор

Статус: рабочая документация API, этап второй недели практикума.

## Общие правила

- Локальный адрес: `http://localhost:3000`
- Формат обмена данными: JSON (UTF-8).
- Идентификатор сессии передаётся в заголовке `X-Session-ID`.
- Формат ошибок: `{"error": "описание ошибки"}`.
- Идентификатор сессии должен иметь формат UUID.

Важно: `X-Session-ID` используется для идентификации сессии, но сам по себе не является полноценным механизмом аутентификации или авторизации.

## 1. Проверка состояния сервиса

**Метод:** GET
**URL:** `/api/health`

Успешный ответ — `200 OK`:

```json
{
  "status": "ok",
  "database": "connected",
  "service": "professional-navigator-api"
}
```

Проверяет доступность backend и подключение к PostgreSQL.

## 2. Выбор трека

**Метод:** POST
**URL:** `/api/track/select`

Заголовок: `X-Session-ID: <UUID>`

Запрос:

```json
{
  "trackType": "explore"
}
```

Допустимые значения:
- `explore` — исследование вариантов;
- `interests` — выбор на основе интересов;
- `known_direction` — уже выбранное направление.

Успешный ответ — `200 OK`:

```json
{
  "sessionId": "fef8f990-9cd0-4c54-b0f3-94b0b12e1c4b",
  "trackType": "explore",
  "status": "selected"
}
```

Возможные ошибки: 400, 401, 422, 500.

## 3. Отправка диагностики

**Метод:** POST
**URL:** `/api/diagnostic/submit`

Заголовок: `X-Session-ID: <UUID>`

Запрос:

```json
{
  "answers": [
    {
      "questionId": "q1",
      "answer": "Мне нравится программирование"
    },
    {
      "questionId": "q2",
      "answer": "Люблю анализировать данные"
    }
  ]
}
```

Требования:
- Массив `answers` должен содержать от 1 до 100 элементов.
- Каждый ответ должен иметь `questionId` и `answer`.
- Допустимые типы ответа: строка, число, логическое значение, массив строк.

Успешный ответ — `201 Created`:

```json
{
  "diagnosticId": "a12b34cd-1234-4567-8901-123456789abc",
  "savedAnswers": 2,
  "status": "submitted"
}
```

Ответы сохраняются в PostgreSQL.

Возможные ошибки: 400, 401, 404, 422, 500.

## 4. Генерация рекомендаций с помощью ИИ

**Метод:** POST
**URL:** `/api/recommendations/generate`

Заголовок: `X-Session-ID: <UUID>`

Запрос:

```json
{}
```

### Логика работы

1. Проверка формата и существования сессии.
2. Получение последней сохранённой диагностики.
3. Получение доступного профиля пользователя.
4. Загрузка активных профессий и профессиональных проб из PostgreSQL.
5. Формирование запроса к AI Gateway.
6. Генерация рекомендаций моделью `GigaChat-2-Pro`.
7. Валидация структурированного ответа модели.
8. Проверка идентификаторов профессий и профпроб по загруженному каталогу.
9. Сохранение результата в таблицу `recommendations`.
10. Возврат сформированных рекомендаций пользователю.

### Успешный ответ — 201 Created

```json
{
  "status": "generated",
  "recommendationId": "60df6779-2890-4fa2-93a9-959df65134f1",
  "sessionId": "72863e2d-f598-4692-9bc8-8f77e98659ba",
  "summary": "Пользователь проявляет интерес к программированию и анализу данных.",
  "hypotheses": [
    {
      "professionId": "ec5a249f-50a3-465d-ad12-c69c83b9180f",
      "title": "Аналитик данных",
      "reason": "Соответствует интересам к анализу данных и решению логических задач.",
      "fitScore": 90
    }
  ],
  "trials": [],
  "nextStep": "Изучить подходящие профессиональные направления.",
  "model": "GigaChat-2-Pro",
  "createdAt": "2026-10-28T11:53:36.017Z"
}
```

Пример сокращён. Реальный ответ может содержать несколько профессий и профессиональных проб.

`fitScore` — оценка соответствия, сформированная ИИ. Она не является результатом стандартизированного психометрического тестирования.

### Обработка ошибок

- `400 Bad Request` — некорректный формат идентификатора сессии или запроса.
- `401 Unauthorized` — отсутствует идентификатор сессии.
- `404 Not Found` — сессия не найдена.
- `409 Conflict` — отсутствует сохранённая диагностика.
- `502 Bad Gateway` — ошибка получения или обработки ответа AI Gateway.
- `503 Service Unavailable` — отсутствует необходимая конфигурация ИИ или доступный каталог.
- `500 Internal Server Error` — внутренняя ошибка сервера.

### Конфигурация

Для работы необходимы переменные окружения:

```env
AI_API_BASE_URL=
AI_API_KEY=
AI_MODEL=GigaChat-2-Pro
```

Секретный ключ хранится только в локальных переменных окружения и не должен попадать в GitHub.

## 5. Сохранение обратной связи

**Метод:** POST
**URL:** `/api/reflection`

Заголовок: `X-Session-ID: <UUID>`

Запрос:

```json
{
  "rating": "useful",
  "comment": "Рекомендации были полезны"
}
```

Допустимые оценки: `useful`, `unsure`, `not_useful`.

Поля `recommendationId` и `comment` необязательны.

Успешный ответ — `201 Created`:

```json
{
  "id": "b12b34cd-1234-4567-8901-123456789abc",
  "created_at": "2026-10-22T12:00:00.000Z",
  "status": "saved"
}
```

Возможные ошибки: 400, 401, 404, 422, 500.

## 6. Получение списка профессий

**Метод:** GET
**URL:** `/api/professions`

Тело запроса не требуется.

Успешный ответ — `200 OK`:

```json
{
  "data": [
    {
      "id": "a12b34cd-1234-4567-8901-123456789abc",
      "title": "Инженер-механик",
      "description": "Описание профессии"
    }
  ],
  "count": 1
}
```

Пример иллюстративный. На момент интеграционного тестирования в локальной базе было 40 профессий.

Возможные ошибки: 500.
